# CODEWAVE

## Industry-Grade Offline Hi-Res Music Player for Android (v1.6.5)

**Product type:** Native Android local music player
**Current release:** v1.6.5 (Production Release)
**Primary platform:** Android phones (Android 8.0+ / API 26+)
**Secondary targets:** Android Auto, tablets/foldables, Wear OS
**Connectivity:** 100% Offline-first; internet optional and only queried for GitHub Release OTA updates
**Account:** None (Zero authentication requirement)
**Cloud library:** None (Local device storage ownership)
**Streaming:** None (Bit-perfect local PCM playback)
**Ads:** None (Completely ad-free)
**Analytics:** None (Strict privacy-first, zero telemetry tracking)
**Primary differentiator:** VS-Code-inspired developer aesthetic combined with audiophile-grade 32-bit floating-point DSP (ViPER/Dolby C++ engine), real-time 1024-point dual-stereo FFT visualizer, zero-layout-shift Studio Lyrics workstation with sing-along mode, and an ultra-fast Room SQLite indexed local library.

---

# 1. PRODUCT VISION

CODEWAVE is a premium, completely local Android music player for people who own their music.

It must:

* discover local audio rapidly
* play music reliably in foreground/background
* expose meaningful technical audio information
* preserve lossless playback whenever the Android audio path permits it
* provide professional library organization
* provide a serious equalizer/DSP system
* remain usable without an internet connection
* feel instantaneous
* survive Android process death
* recover gracefully from media/file/device changes
* integrate properly with Android system media controls
* provide optional GitHub Release-based sideload update discovery
* maintain a polished, coherent visual system

CODEWAVE is **not**:

* a streaming service
* a downloader
* a social network
* an account-based music platform
* a cloud music locker
* a generic MP3 player with a themed skin

# 2. CORE PRODUCT PRINCIPLES

## P0 — Local ownership

The user's music remains on their device.

No account is required.

No cloud database is required.

No network is required for:

* scanning
* browsing
* searching
* playlists
* favorites
* playback
* EQ
* sleep timer
* queue management
* album art
* metadata editing

---

## P0 — Playback reliability beats visual complexity

The player must never sacrifice playback reliability for animations.

If the device is under memory pressure:

1. visual effects degrade
2. album-art prefetching is reduced
3. expensive visualizers disable
4. playback remains unaffected

---

## P0 — Never lie about audio quality

CODEWAVE must distinguish:

**File properties**

from

**actual playback/output properties.**

For example:

> FLAC · 24-bit · 96 kHz

means the file contains that format.

It must NOT imply that the user is necessarily receiving 24-bit/96-kHz output from the hardware.

The UI should therefore distinguish:

**SOURCE**

`FLAC · 24-bit · 96 kHz · Lossless`

and, where technically obtainable:

**OUTPUT**

`48 kHz · 24-bit · PCM`

If output information cannot be reliably determined:

`Output information unavailable`

Never fabricate it.

# 27. AUDIO ENGINE

## Primary Engine: Jetpack Media3 ExoPlayer with In-Process PCM Interception

CODEWAVE uses Jetpack Media3 ExoPlayer coupled with a custom `ViperAudioProcessor` that intercepts the raw decoded PCM audio stream directly before hardware `AudioTrack` rendering.

Audio Processing Pipeline:

```text
Local Audio File (FLAC / WAV / ALAC / MP3 / OGG / AAC / OPUS)
  │
  ▼
ExoPlayer Audio Decoder (MediaCodec / Extractor)
  │
  ▼ Raw 16-bit / 32-bit Float PCM Stream
[ViperAudioProcessor] (Media3 BaseAudioProcessor)
  │
  ├── 1. PCM to Float32 Normalization ([-1.0, 1.0] zero-allocation working buffer)
  │
  ├── 2. Live Audio Spectrum Tap
  │      └── AudioVisualizerProcessor (1024-pt Dual Stereo Radix-2 FFT, 24 Bark Bands, AGC)
  │
  ├── 3. Studio Master DSP Engine
  │      ├── Native C++ ViPER/Dolby JNI Library (libviper.so)
  │      │   ├── 10-Band Parametric Equalizer (Biquad Filter Cascades)
  │      │   ├── Master Preamp Gain (-12 dB to +12 dB)
  │      │   ├── Soft-Knee Limiter Anti-Clipping Guard
  │      │   └── ViPERFX Acoustic Suite:
  │      │       ├── Dynamic Bass (80Hz Butterworth sub-harmonic synthesis)
  │      │       ├── Vocal Clarity (3.2kHz presence shelf)
  │      │       └── IRS Convolver (Time-domain FIR filter from impulse response)
  │      └── Pure Kotlin Audiophile Fallback (DolbyLevelEqualizer)
  │
  ▼ Clamped / Limited PCM Stream
Hardware AudioTrack Sink (Direct bit-perfect or high-res Android audio path)
```

Key Architectural Advantages:
* **Zero Microphone Permissions**: Visualizer receives true digital audio stream directly from the decoder pipeline in-process, bypassing Android's restrictive `RECORD_AUDIO` permission.
* **Bit-Perfect Direct Passthrough**: When DSP is disabled (`isEnabled = false`), audio samples pass unmodified through the pipeline.
* **Low Latency & Glitch-Free**: Audio processing happens on the dedicated high-priority ExoPlayer audio thread with zero memory re-allocations per frame.

# 37. EQ MODES & CONSOLE CONTROLS

The Equalizer screen (`EqualizerScreen.kt`) is styled as a unified hardware audio rack console.

### 1. Studio Master Console & Status Readout
* **Master Power Switch**: Enables/disables entire DSP pipeline. When disabled, the audio path operates in **Bit-Perfect Direct** mode with zero coloring.
* **DSP Status Readout**:
  * `FLOAT32 MASTER DSP · ACTIVE` (Green indicator): Native C++ JNI engine processing.
  * `LEGACY EQUALIZER FALLBACK` (Yellow indicator): Pure Kotlin Biquad filter engine.
  * `BYPASSED (BIT-PERFECT DIRECT)` (Gray indicator): Raw unmolested PCM audio stream.
* **Quick Reset ("FLAT")**: Instant button to reset all 10 bands to 0.0 dB without disabling the engine.

### 2. Parametric Frequency Visualizer (`RealTimeEQCurveCanvas`)
* Real-time dynamic frequency curve canvas rendered above the sliders.
* Uses cubic Bézier spline interpolation across all 10 frequency nodes.
* Renders continuous curve in cyan accent with glowing subtle gradient fill representing the $\pm 12\text{ dB}$ dynamic response.

### 3. 10-Band Parametric Console Chassis
* Frequencies: `31 Hz`, `62 Hz`, `125 Hz`, `250 Hz`, `500 Hz`, `1 kHz`, `2 kHz`, `4 kHz`, `8 kHz`, `16 kHz`.
* High-precision vertical faders (`CWVerticalFader`) with $\pm 12\text{ dB}$ range, center 0 dB detent, and frequency labels.
* Gain values persist automatically across tracks and app restarts via `EqualizerRepository`.

### 4. Master Preamp Gain Console
* Bipolar center-zero hardware slider (-12.0 dB to +12.0 dB).
* Quick dB Jump Chips: Direct tap buttons for `-6 dB`, `-3 dB`, `0 dB`, `+3 dB`, `+6 dB` to quickly manage headroom.

### 5. Limiter Anti-Clipping Guard
* Soft-knee dynamic limiter with lookahead protection.
* Prevents digital harshness, inter-sample peaks, and digital clipping when boosting multiple equalizer bands or applying preamp gain.
* Status badge: `PROTECTED` (Green) when active.

### 6. ViPERFX Acoustic Suite
* **ViPER Dynamic Bass**:
  * 80 Hz Butterworth sub-harmonic synthesis & 5 Hz DC filter.
  * Adjustable gain: `0.0 dB` to `+12.0 dB` (Default: `+4.0 dB`).
* **ViPER Vocal Clarity**:
  * 3.2 kHz presence shelf for crystal clear dialog, podcast speech, and acoustic vocals.
  * Adjustable gain: `0.0 dB` to `+12.0 dB`.
* **IRS Convolver (Impulse Response Engine)**:
  * High-performance time-domain FIR convolution filter.
  * Supports loading custom `.irs` and `.wav` impulse responses directly from local device storage (e.g. Sony DSEE, tube amplifier emulations, studio room reverbs).

# 39. DSP SAFETY & HEADROOM

To guarantee studio audio fidelity without digital distortion:

* Preamp attenuation automatically recommended when aggregate band boost exceeds $+6\text{ dB}$.

# 76. VISUALIZER & SPECTRUM ANALYZER

CODEWAVE features a real-time, hardware-synchronized dual-channel audio spectrum visualizer integrated directly into the `NowPlayingScreen` within `CWAudioWaveformBox.kt` and `AudioVisualizerProcessor.kt`.

Architecture & DSP Pipeline:

```text
ExoPlayer Decoded PCM Stream (Float32 [-1.0, 1.0])
  │
  ▼
[ViperAudioProcessor.feedAudio()] (Zero microphone / RECORD_AUDIO permissions)
  │
  ├── Stereo Ring Buffers (Left & Right channels, 1024 samples each)
  │
  ▼
Dual 1024-Point Cooley-Tukey Radix-2 FFT (Hann Windowed, Zero Garbage Collection)
  │
  ├── 512 Positive Frequency Bins (~43.06 Hz resolution per bin)
  │
  ├── 24 Perceptual Bark Scale Bands (30 Hz Sub-Bass to 16 kHz Treble Air)
  │
  ├── True Logarithmic Decibel (dB) Compression (-48.0 dB Dynamic Floor)
  │
  ├── Dynamic Auto-Gain Control (AGC with Leaky Peak Follower)
  │
  ▼
48 Symmetrical Stereo Soundstage Bars:
  ├── Left Channel: Bars 0–23 (Treble at 0 ─── Bass / Kicks at 23)
  └── Right Channel: Bars 24–47 (Bass / Kicks at 24 ─── Treble at 47)
  │
  ▼
Display-Timed Choreographer Ballistics (withFrameNanos at 60Hz / 90Hz / 120Hz):
  ├── Instant Attack (Speed 36.0/s) on Percussive Transients
  ├── Smooth Gravitational Decay (Speed 14.0/s) on Analog Meter Falloff
  └── 0% CPU Idle Suspension when Playback is Paused
```

### 1. In-Process Audio Interception (Zero Permissions)
* Intercepts raw Float32 decoded PCM samples between ExoPlayer's decoder and Android's `AudioTrack`.
* Operates entirely in-process without requiring Android's sensitive `RECORD_AUDIO` microphone permission.
* Works identically across headphones, phone speakers, USB DACs, and Bluetooth A2DP audio devices.

### 2. High-Precision FFT Spectrum Analysis
* **Transform Size**: 1024-point complex FFT with pre-calculated Hann window table and bit-reversal lookup arrays.
* **Frequency Mapping**: 512 positive frequency bins grouped into 24 perceptual Bark scale bands:
  * Single/dual bin grouping for sub-bass (30–120 Hz) and kick drum transients.
  * Psychoacoustic grouping for vocal formants (300 Hz – 3 kHz).
  * High-frequency averaging for upper treble and cymbal sparkle (3 kHz – 16 kHz).
* **Decibel Dynamics**: Converts raw magnitude to true decibels: $\text{dB} = 20 \log_{10}(\text{magnitude})$ with a $-48.0\text{ dB}$ floor.
* **Auto-Gain Control (AGC)**: Fast-attack peak tracker with 2.5-second leaky decay adapts continuously across quiet acoustic recordings and compressed electronic music.

### 3. Symmetrical Stereo Soundstage Projection
* 48 discrete bars rendered in vertical dual-tone gradients (`#58A6FF` to `#1F6FEB`).
* **Center-Anchored Lows**: Sub-bass and kicks meet symmetrically at the energetic center (Bars 23 & 24), creating an intuitive physical soundstage visualization.
* **Stereo Channel Separation**: Left channel maps to left wing (bars 0–23), Right channel maps to right wing (bars 24–47).

### 4. Hardware-Synchronized 120Hz Display Ballistics
* Rendered via Compose `Canvas` driven by `withFrameNanos`, locking frame execution to the device's native display refresh rate (60Hz, 90Hz, 120Hz).
* **Asymmetric Ballistics**:
  * Snappy attack (speed 36.0/s) triggers instantaneous visual kick on transient drum hits.
  * Exponential decay (speed 14.0/s) provides organic analog meter needle falloff.
* **Complete Idle Suspension**: When playback is paused and bar heights settle below baseline (`0.045f`), the `LaunchedEffect` coroutine suspends cleanly via `snapshotFlow`, consuming **0% CPU** and conserving 100% battery.

### 5. Integrated System Volume Touch Bar
* Embedded directly into the visualizer card header.
* Shows active status indicator dot and live Android `STREAM_MUSIC` volume percentage (`VOLUME 85%` or `MUTED`).
* Supports single-tap and continuous horizontal drag gestures with haptic feedback ticks.
* Listens to Android system volume changes via `ContentObserver`, updating in real-time when hardware volume rocker buttons are pressed.

## Channel A — Google Play

## Channel B — In-App GitHub Releases OTA Engine (`OtaUpdateManager`)

```text
CODEWAVE Client
   │

   │

   ├── Parse tag_name (e.g. "v1.6.5") & extract SemVer numbers
   ├── Compare against local BuildConfig.VERSION_NAME
   ├── Extract markdown body (Changelog) and browser_download_url (.apk)
   │
   ▼ Update Available
In-App Presentation (`OtaUpdateDialog` / `SettingsScreen`):
   ├── Displays modal popup on launch (or manual check in Settings)
   ├── Renders release version badge & changelog
   ├── Action: "Download & Install"
   │
   ▼ Streaming Download (Ktor / HttpURLConnection)
Direct Cache Download:
   ├── Streams bytes to context.cacheDir/updates/codewave-vX.X.X.apk
```

* **Dismissible & Respectful**: Users can dismiss the update dialog at any time; updates never force-abort active audio playback.

# 122. AUTOEQ INTEGRATED PROFILE DATABASE

CodeWave embeds an offline AutoEq parametric database covering standard consumer and audiophile headphones and in-ear monitors (IEMs).

Targets supported:
* Harman Over-Ear Target (2018)
* Harman In-Ear Target (2019)
* oratory1990 Studio Reference Target

Rules:
1. Pure local JSON asset storage (`assets/autoeq/models.json`).
2. Translates frequency curves into calibrated 10-band graphic EQ levels:
   * 31 Hz, 62 Hz, 125 Hz, 250 Hz, 500 Hz, 1 kHz, 2 kHz, 4 kHz, 8 kHz, 16 kHz.
3. Automatically computes safe negative pre-amplification (`preampDb`) to prevent digital clipping / inter-sample peaks when boosting specific frequency bands.
4. Prefix and model fuzzy searching integrated directly into the Equalizer Studio console.

# 123. PER-DEVICE AUDIO HARDWARE OUTPUT PROFILES

Audio hardware routing changes frequently throughout a developer's day (Bluetooth ANC headphones at work, USB DAC at desk, 3.5mm aux in car, phone loudspeaker).

Capabilities:
1. Detects active output hardware via Android `AudioDeviceCallback`:
   * `BLUETOOTH_A2DP`
   * `WIRED_HEADPHONES` / `WIRED_HEADSET`
   * `USB_HEADSET` / `USB_DEVICE`
   * `BUILTIN_SPEAKER`
2. Remembers last applied sound profile per unique audio device.
3. Automatically switches EQ curve and DSP parameters upon device connection/disconnection without user intervention.
4. Non-intrusive HUD telemetry banner alerts user to the active profile routing change.

# 124. MULTI-QUEUE WORKSPACES (VS CODE TABS)

A workstation-grade queue management system inspired by code editor tabs.

Architecture:
1. Multiple concurrent playback queues maintained in memory:
   * `MAIN` (Root playback queue, protected against deletion)
   * Secondary custom workspaces (e.g. `SCRATCHPAD`, `FOCUS MIX`, `STUDIO REVIEW`)
2. Tab bar embedded within the Terminal Queue Drawer:
   * Visual indicator `*` demarcates the actively playing workspace.
   * Tap any tab to view and edit its contents without disturbing current playback.
3. Actions:
   * `[PLAY]`: Swaps active playback to the currently viewed workspace.
   * `[CLEAR]`: Empties queue of the inspected workspace.
   * `[+]`: Opens modal to create a named workspace.

# 125. ATOMIC CONFIGURATION & LIBRARY BACKUP/RESTORE

Zero-cloud, 100% offline data sovereignty.

Engine:
1. Export Engine:
   * Serializes all Room database playlists, track mappings, favorite track IDs, custom parametric EQ curves, and workstation settings into single human-readable `.json` payload.
   * Uses Android Storage Access Framework (`ActivityResultContracts.CreateDocument("application/json")`).
2. Restore Engine:
   * Reads `.json` stream via SAF (`ActivityResultContracts.OpenDocument`).
   * Atomically verifies schema version (`version: 1`).
   * Restores playlists, restores favorites, saves custom EQ presets, updates workstation preferences, and triggers an immediate local MediaStore reconciliation.
3. Zero telemetry, zero external network requests. Data stays strictly in user-selected local storage.
